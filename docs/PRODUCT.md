# PRODUCT.md

# Mirror Customizing App — Product Requirements

## Core
- 앱 실행 직후 첫 화면은 Mirror Camera.
- Mirror는 전면 카메라 + 좌우 반전 + edge-to-edge.
- 앱 전체 Portrait only. Landscape 대응 없음.
- Home에는 보유 거울 개수, 설정, 거울 보기, 거울 꾸미기만 표시.
- 거울 꾸미기 → 현재 사용 중인 거울 Editor로 즉시 진입.
- Main Tab: 홈 / 상점 / 내 거울.
- Mirror는 immersive full-screen. Tab Bar를 표시하지 않는다.

## Mirror (확정)
Mirror 화면의 액션은 **홈으로 / 촬영** 둘뿐이다.

### 줌 없음 (확정)
- 거울 카메라에는 **줌이 없다.** 사용자 줌 / pinch / 프로그램 줌 / 디지털 확대 전부 없다.
- 기기 줌은 항상 1.0이고, 쓸 수 있는 format 중 **화각이 가장 넓은 것**을 고른다.
- **거울 geometry가 먼저다.** 프레임 두께(108 / 108 / 180 / 220)와 Camera Area(864 × 1940)는
  확정값이고, 카메라 때문에 바꾸지 않는다. Camera Area는 언제나 카메라로 꽉 찬다.
- Camera Area(세로로 김)와 카메라 소스(4:3)는 비율이 다르므로 가로 일부는 잘린다.
  이건 디지털 줌이 아니라 비율을 맞추면서 생기는 것이고, 프레임을 바꾸지 않는 한 피할 수 없다.
- 화면에서 보는 화각과 촬영 결과의 화각이 같다.
- Editor의 확대/이동은 캔버스 편집 기능이라 그대로 있다. 이 정책은 실제 거울 화면에만 해당한다.

- 기본 상태: Camera + Decoration만. 다른 UI 없음.
- 화면 탭 → 홈으로 + 촬영 표시.
- 마지막 interaction 후 4.2초 → 다시 숨김.
- 다시 탭하면 재표시.
- 홈으로 → Home.
- Decoration은 항상 표시. On/Off 없음.
- Freeze 없음. Zoom 없음. 화면 밝기 조절 없음.

## Capture (확정)
- 촬영 결과 = 지금 보고 있는 세로 Mirror 화면 그대로.
- 화면과 동일한 crop / 좌우 반전 / Decoration 위치 / 화면 비율.
- 결과는 항상 Portrait. orientation metadata가 아니라 실제 pixel 기준.
- 화면 screenshot이 아니라 원본 camera frame + Decoration을 합성한다.
- transient controls(홈으로, 촬영 버튼 등)는 결과 이미지에 포함하지 않는다.
- 저장은 Photos. 사진 추가 권한(add-only)만 사용한다.

## Editor (Free Canvas — 최신)
- **1080 × 2340 거울 한 장 전체를 자유롭게 꾸민다.**
- 상 / 하 / 좌 / 우를 고르는 단계는 없다. (기존 4면 Side Editing 정책은 폐기)
- Editor에 들어오면 거울 한 장이 통째로 화면에 맞춰 보인다.
- Camera Area는 **안내용 얇은 점선**일 뿐 장식 금지 구역이 아니다.
- Drawing / Sticker / Photo Sticker를 Camera Area 위에도 놓을 수 있다.
- 프레임과 Camera Area의 경계를 가로지르는 장식도 잘리지 않는다.
- Editor에서는 Camera Area까지 배경색으로 채워 한 장의 연속된 캔버스처럼 보인다.
- Drawing, Brush, Undo/Redo.
- Photo → Background Removal → Sticker (기기 내 처리).
- Move / Resize / Rotate / Flip / Duplicate / Lock / Opacity.
- Text, Background Color, Preview, Save. (Layers UI는 후속)
- 위치/크기는 0...1 normalized coordinate 우선.

## Editor Viewport
- 진입 시 거울 한 장 전체가 화면에 맞춰 보인다(맞춤 = 배율 1).
- Pinch로 확대, 빈 공간 드래그로 이동. 맞춤보다 더 축소되지는 않는다.
- "맞춤"은 언제나 거울 한 장 전체로 되돌린다.
- 확대 중에도 캔버스 밖 빈 공간은 보이지 않는다.
- Side 선택 / Workspace Gutter / Scroll Handle / Mini Map은 Free Canvas 전환과 함께 제거됐다.

## Sticker
- 기본 제공 스티커는 **손그림 두들 42종**이다. 개발용 placeholder는 전부 교체됐다.
- 갈래(전체 / 러블리 / 반짝 / 다이어리 / 재미 / 심볼)로 나눠 고른다.
- 강조색이 있는 6종(체리 · 꽃 · 해 · 구름 · 풍선 · 케이크)은 색이 실루엣의 일부라 색을 바꾸지 않는다.
- 예전에 저장한 거울의 옛 스티커는 **계속 보인다.** 고르는 목록에만 나오지 않는다.
- 단색 template 스티커는 색을 바꿀 수 있다. 기본값은 잉크색.
- 사진 스티커처럼 원본 색을 유지해야 하는 스티커는 색 변경을 지원하지 않는다.
- 스티커를 옮기는 동안에는 아주 약한 촉각 피드백만 준다. 프레임마다 울리지 않고 시간·이동 거리로 제한한다.
- 배치가 끝나면 `완료`로 선택을 해제한다. 선택 해제 시 한 번 더 또렷한 피드백을 준다.
- 이미 놓은 스티커는 다시 탭해서 선택하고 계속 편집할 수 있다. 잠긴 스티커도 선택은 된다.
- 선택은 항상 하나다. 다른 스티커를 고르면 이전 선택은 풀린다.
- 재선택 시 스티커가 이미 충분히 보이면 화면을 움직이지 않는다. 화면 밖이면 배율을 유지한 채 최소한만 끌어온다.
- 회전하거나 작은 스티커도 눈에 보이는 자리를 누르면 잡힌다 (최소 tap target 44pt).
- 스티커 도구에서는 빈 곳을 한 손가락으로 끌면 화면이 움직인다. → **Editor 제스처 정책** 참고.
- 제스처 우선순위: 크기·회전 handle → 스티커 → 빈 캔버스(화면 이동).
- 스티커는 Camera Area를 포함한 캔버스 어디에나 놓을 수 있다. 캔버스 밖으로만 나가지 못한다.

## Editor 제스처 정책

한 손가락이 무엇을 하는지는 **도구 + 그리기 모드 + 손가락이 내려온 자리** 셋으로만 정해진다.
규칙은 `EditorGesturePolicy.oneFingerAction` 한 곳에 있고, 도구마다 따로 판단하지 않는다.

| 도구 | 한 손가락 | 두 손가락 | Pinch |
|---|---|---|---|
| 그리기 (그리기 모드) | 획을 그린다 | 화면 이동 | 확대 (1…4) |
| 그리기 (손바닥 모드) | 화면 이동 | 화면 이동 | 확대 (1…4) |
| 지우개 | 지운다 | 화면 이동 | 확대 (1…4) |
| 스티커 · 사진 스티커 · 텍스트 | 오브젝트 위 → 오브젝트 이동 / 빈 곳 → 화면 이동 | 화면 이동 | 확대 (1…4) |

- **두 손가락은 언제나 화면 이동/확대다.** 오브젝트 위에서 시작해도 마찬가지라,
  스티커가 화면을 거의 덮고 있어도 캔버스를 옮길 수 있다.
- **잠긴 오브젝트** 위에서 끌면 오브젝트는 그대로 있고 화면이 움직인다. 선택은 여전히 된다.
- **끌기와 tap의 판정 범위가 다르다.** 제자리 tap만 최소 44pt까지 넓히고,
  끌기는 눈에 보이는 크기 그대로 본다 — 그래야 작은 스티커 옆 여백을 밀 수 있다.
- **Pinch 중에 오브젝트가 커지지 않는다.** 두 손가락 경로는 viewport state만 바꾼다.
- **화면 이동 / 확대 / 맞춤은 실행 취소에 쌓이지 않는다.** history가 다루는 것은 편집 데이터뿐이다.
- 두 손가락을 대려다 손가락이 44pt 미만으로 미끄러진 자국은 획으로 남기지 않는다.

### 그리기 ↔ 손바닥
- 그리기 도구를 고르면 **항상 그리기 모드**로 시작한다.
- 캔버스 바로 아래 잉크 컨트롤(연필 / 손바닥)로 즉시 바꾼다. 새 카드나 모달을 띄우지 않는다.
- 붓 · 색 · 굵기를 바꿔도 모드는 유지된다. 다른 도구에 갔다 오면 그리기로 돌아온다.
- 손바닥 모드는 획을 만들지도, 기존 획을 지우지도 않는다.
- 손바닥 모드에서도 Camera Area 안에 그릴 수 있다 — 그리기는 계속 Free Canvas다.

## Photo Sticker
- 스티커 고르기 맨 위에 "내 사진으로 만들기".
- 사진은 1장씩 고르고, **기기 안에서** 배경을 지운다. 서버로 보내지 않는다.
- 처리 중에는 "사진을 스티커로 만드는 중..."을 보여주고 캔버스를 잠근다.
- 피사체를 못 찾으면 앱이 죽지 않고 물어본다 — 다시 고르기 / 원본 그대로 넣기 / 취소.
- 결과는 배경이 투명한 이미지이고, 피사체 크기에 맞춰 잘린 뒤 약간의 투명 여백이 남는다.
- 사진 스티커는 **원본 비율을 유지한다.** 정사각형으로 만들지 않는다.
- 사진 스티커는 원본 색을 그대로 쓰므로 색 변경을 지원하지 않는다.
- 이동 / 크기 / 회전 / 뒤집기 / 복제 / 잠금 / 투명도 / 삭제 / 완료 / 재선택은 기본 스티커와 완전히 같다.

### 크기 조절 정책 (모든 스티커 공통)
- **비율이 변하지 않는다.** 크기를 키우거나 줄여도 원본 가로:세로가 그대로다.
  눌리거나 늘어나는 크기 조절은 없다. 사진 스티커는 원본 사진 비율이 기준이다.
- **최대 크기 제한이 없다.** 캔버스보다 2배 · 3배 · 5배로 키울 수 있다.
- **스티커가 캔버스를 넘어가도 된다.** 넘어간 부분만 캔버스 경계에서 잘린다 —
  앱이 스티커를 캔버스 안으로 억지로 줄이지 않는다.
- 너무 작아지는 것만 막는다(아주 작은 최소 크기).
- 이 정책은 거울 꾸미기와 스티커 만들기에서 **똑같이** 적용된다.
- 사진을 넣었다고 거울 보관 슬롯을 더 쓰지 않는다.
- 저장한 뒤에는 홈 미리보기 / 내 거울 목록 / 실제 Mirror / Capture 모두에서 같은 사진이 보인다.
- 거울을 복제해도 사진은 다시 복사되지 않고 같은 asset을 참조한다.
- 앱을 완전히 끄고 다시 켜도 사진이 그대로 남는다. 이미지는 거울 파일이 아니라 별도 PNG로 보관한다.

## Text
- 툴바의 `텍스트` → 입력 시트 → `추가`를 눌러야 만들어진다.
- 여러 줄 입력. 빈 문자열 / 공백만은 만들 수 없다. 최대 100자.
- 새 텍스트는 **보고 있는 화면 한가운데**에 생긴다. 카메라 영역도 그대로 유효하다.
- 이동 / 크기 / 회전은 스티커와 같은 방식. 크기는 글자 크기만 바뀌어 **찌그러지지 않는다.**
- 컨트롤: 내용 수정 / 색 / 글꼴 / 정렬 / 복제 / 잠금 / 삭제 / 완료 + 투명도.
- 글꼴 11종 — 기본 / 개구 3종(가늘게·기본·굵게) / 감자꽃 / 하이멜로디 / 주아 / 나눔붓 / 나눔펜 / 푸어스토리 / 싱글데이.
- 글꼴 고르기는 이름 목록이 아니라 **각 줄이 그 글꼴로 "오늘도 예쁘게"를 보여주는** 화면이다. 추천 / 손글씨 / 강조로 묶는다.
- 앱 UI 글씨(개구 고정)와는 별개다 — 거울 글씨를 바꿔도 버튼 글씨는 그대로다.
- 크기 조절은 스티커와 같은 체감이다. 조금 끌면 조금만 커진다.
- 정렬 왼쪽 / 가운데 / 오른쪽, 기본값 가운데.
- 내용을 고쳐도 같은 텍스트다 — Undo하면 이전 내용으로 돌아간다.
- 잠긴 텍스트도 선택은 된다. 이동 / 크기 / 회전만 막힌다.
- 스티커와 텍스트는 **동시에 선택되지 않는다.** 한 번에 하나만.
- 겹치면 화면에서 위에 보이는 것이 잡힌다. 같은 zIndex면 텍스트가 위다.
- 테두리 / 그림자 / 배경 박스 같은 고급 스타일은 후속 Phase.

## External Artwork (외부에서 만들기)
- 내 거울의 `+ 거울 만들기`에서 **꾸미러에서 만들기 / 외부에서 만들기**를 고른다.
- 외부에서 만들기: 작업 가이드 저장 → 그림 앱에서 작업 → 투명 PNG 내보내기 → 가져오기.
- 작업 가이드는 1080 × 2340 투명 PNG다. 거울 외곽선과 카메라 영역 점선만 들어 있어 밑에 깔고 그리기 좋다.
- 특정 앱을 요구하지 않는다. 투명 PNG로 내보낼 수 있는 그림 앱이면 무엇이든 된다.
- **외부 디자인은 프레임용 overlay다.** 점선 안쪽(카메라 영역)은 **가져올 때 자동으로 지워진다.**
  가이드 안쪽에 그려도 남지 않으니 프레임 부분을 꾸민다.
  (카메라 영역에 콧수염 / 하트를 얹고 싶으면 Editor의 그리기 / 스티커 / 텍스트를 쓴다.)
- 가져온 디자인은 **캔버스 전체에 딱 맞는 고정 레이어**다. 앱에서 옮기거나 키우거나 돌리지 않는다 —
  사용자가 가이드 기준으로 정한 위치를 그대로 지킨다.
- 사진에서 / 파일에서 두 경로로 가져온다.
- 정확히 1080 × 2340이면 그대로, 같은 비율(9 : 19.5)로 더 크면 자동으로 줄인다.
- 비율이 다르면 늘려서 왜곡시키지 않고 "작업 가이드와 비율이 달라요"로 되묻는다.
- 배경을 꽉 채워 와도 막지 않는다 — 카메라 영역은 어차피 지워지므로 프레임만 남는다.
- 가져오면 바로 저장하지 않는다. 실제 거울 모양 위에 얹어 보여주고 [다시 선택] / [이 디자인 사용]을 고른다.
- 사용하면 그 디자인이 깔린 채로 Editor가 열린다. 그 위에 그리기 / 스티커 / 사진 / 텍스트를 계속 얹을 수 있다.
- 외부 디자인은 캔버스를 눌러 고르지 않는다. 화면 전체를 덮어 다른 장식 선택을 막기 때문이다 —
  선택은 `레이어` 목록에서 한다. 컨트롤은 교체 / 투명도 / 삭제뿐이다.
- 거울을 복제해도 그림 파일은 하나를 함께 본다.

## Decoration 순서 / 레이어
- 스티커 / 사진 스티커 / 텍스트 / 외부 디자인은 **하나의 순서**를 공유한다.
- 툴바의 `레이어`에서 목록을 보고 끌어서 순서를 바꾼다. **위가 앞, 아래가 뒤.**
- 순서를 바꾸면 Editor / 홈 미리보기 / 내 거울 / 실제 Mirror / Capture가 즉시 같이 바뀐다.

## Editor 진입 경로 (저장 정책의 기준)
저장이 무엇이 될지는 거울의 origin이 아니라 **어디서 Editor에 들어왔는가**가 정한다.

- 홈 → 거울 꾸미기 = `editCurrent`. 지금 쓰는 거울을 **그 자리에서 고친다.** **이름을 절대 묻지 않는다.**
  - 그 거울이 이미 내 거울에 있으면 같은 거울을 갱신한다. 이름 유지, 슬롯도 늘지 않는다.
  - 목록에 없는 기본 거울이면 **첫 저장에서만** 새 거울을 만든다 — 이름은 자동으로 "나의 거울"("나의 거울 2", "나의 거울 3" …), 슬롯 1개. 같은 Editor에서 다시 저장하면 방금 만든 거울을 갱신한다.
- 내 거울 → 특정 거울 꾸미기 = `editCurrent`. **그 거울을 그 자리에서 고친다.**
  - 같은 거울 id를 갱신한다. 새 거울이 생기지 않고, 슬롯도 늘지 않고, 이름도 다시 묻지 않는다.
  - 지금 쓰는 거울이 아니어도 **적용 상태는 바뀌지 않는다.** 적용은 `적용`이 한다.
  - 저장하기 전까지는 원본이 그대로다. Editor는 복사본에서 작업한다.
- 내 거울 → 특정 거울 **복제** = `duplicate`. **여기만** 새 거울(새 id)을 만든다.
  원본은 그대로 두고 이름은 "○○ 복사본"이다. 꾸미기와 복제는 서로 다른 동작이다.
- 내 거울 → + 거울 만들기 = `createNew`. 빈 거울에서 시작해 새 거울을 만든다.
- 새 거울이 만들어지면 그 거울이 바로 현재 거울이 된다.
- 저장하기 전에 취소하면 내 거울 / 슬롯 / 현재 거울 무엇도 바뀌지 않는다.

## 저장 / 복원 (기기 안)
- 내 거울과 사진 스티커는 **기기에 저장된다.** 앱을 완전히 끄고 다시 켜도 그대로다.
- 다시 켜면 마지막에 쓰던 거울이 그대로 현재 거울이다.
- 저장되는 것: 거울 이름 / 출처 / 배경 / 그림 / 스티커 / 사진 스티커 / 텍스트 / 외부 디자인 / 레이어 순서 / 보관 슬롯.
- 사진 스티커와 외부 디자인 이미지는 거울마다 복사되지 않는다. 거울을 복제해도 같은 파일 하나를 함께 본다.
- 어떤 거울도 쓰지 않게 된 사진은 정리된다. 다른 거울이 아직 쓰고 있으면 지우지 않는다.
- 저장 시점은 저장 / 만들기 / 복제 / 삭제 / 적용처럼 **의미 있는 순간**이다. 꾸미는 도중에는 저장하지 않는다.
- 저장 파일을 읽지 못해도 앱이 죽지 않는다. 원본을 지우지 않고 따로 치워둔 뒤 빈 상태로 시작한다.
- 앱을 삭제했다 다시 설치하면 기기 안 데이터는 사라진다 — 클라우드 백업은 아직 없다.

## Mirror 저장 / 보관
- 이름은 **내 거울에서 새 결과물을 만들 때만** 묻는다(복제 / + 거울 만들기). 최대 24자.
- 홈 저장은 언제나 이름 없이 끝난다.
- 새 거울(`duplicate` / `createNew` / 기본 거울 첫 저장)은 슬롯 1개를 쓴다.
- 보관 공간(슬롯)은 **내가 만든 거울만** 차지한다. 상점에서 받은 기본 / 구매한 거울은 차지하지 않는다.
- 무료 보관 공간은 3칸이다.
- 보관 공간이 가득 차면 새 거울 저장을 막고, 공간을 늘리라고 안내한다. 기존 거울 덮어쓰기는 계속 된다.
- 보관 공간 확장은 조각으로 구매한다. 1회 구매 시 5칸. **가격은 미정이고, 아직 조각을 차감하지 않는다.**
- 보관 공간과 조각은 서로 다른 개념이다. 공간을 늘려도 조각 잔액 계산은 별도다.

- 20 조각 등록 비용은 **문구로만** 알린다. 지금은 차감하지 않는다.
- 저장하면 판매 정보만 남는다 — 거울 종류(내가 만든)도, 보관 슬롯도, 조각도, 상점 목록도 바뀌지 않는다.
- 실제 등록 / 판매 / 정산은 로그인과 서버가 붙는 다음 단계다. 지금은 "등록됐다"고 말하지 않는다.

## Sticker Creator (V-5A 확정)

사용자가 앱 안에서 **스티커를 직접 만든다.** 결과물은 두 가지다:

- 배경이 완전히 투명한 스티커 PNG 한 장
- **다시 편집할 수 있는** 스티커 프로젝트 (완성 PNG만 저장하지 않는다)

진입: Editor → 스티커 → `스티커 만들기`. 빈 캔버스에서 시작하거나 사진으로 시작한다.

### 도구

사진 · 그리기 · 스티커(두들 42종) · 텍스트 · 레이어. 거울 Editor와 **같은 것을 쓴다** —
같은 붓, 같은 글꼴, 같은 제스처, 같은 실행 취소.

- 사진은 **기기 안에서 배경을 지운다.** 서버로 보내지 않는다.
  스티커는 배경 제거가 기본 정책이라 "원본 그대로 넣기"를 주지 않는다 — 실패하면 다시 고른다.
- 사진은 여러 장 넣을 수 있다.
- 두들 42종은 거울에서 쓰는 것과 같은 목록이다. 예전 legacy 스티커는 여기 나오지 않는다.
- 텍스트는 거울과 같은 글꼴 11종을 쓴다.

### 저장

- 이름을 입력한다. 기본값은 "내 스티커" / "내 스티커 2" …
- 편집해서 저장하면 **같은 스티커가 바뀐다.** 새 스티커가 생기지 않고 이름도 유지된다.
- 취소하면 원본 스티커와 완성 PNG 모두 그대로다.
- 스티커는 기기에 저장된다. 거울 저장 파일과 섞이지 않는다.

### 아직 아닌 것

내 스티커 목록 화면 · 거울 Editor에서 내 스티커 고르기 · 상점 등록 · 판매 · 구매는
다음 단계(V-5B)다. 지금은 만들고 저장하는 것까지다.

## AI 스티커 (A-1A)

Sticker Creator 안에서 **한 줄로 설명하면 스티커가 나온다.** 배경은 투명하다.

| | |
|---|---|
| 진입 | Sticker Creator → `AI` |
| 입력 | 설명 한 줄 (최대 200자) |
| 결과 | 1024 × 1024 투명 PNG 레이어 하나 |
| 만드는 방식 | AI가 그림을 만들고, **배경은 기기가 지운다**(사진 스티커와 같은 기능) |
| 가격 | **서버가 정한다** (현재 6 조각) |
| 로그인 | **필요하다** — 조각을 쓰기 때문이다 |

만들어진 그림은 **레이어 하나로 들어온다.** 사진 스티커와 똑같이 옮기고 키우고 돌릴 수 있고,
그 위에 그림을 그리거나 텍스트를 얹어도 된다. 완성된 스티커 한 장에 AI 레이어가 여러 개
들어갈 수도 있다.

### 조각

- 차감도 환불도 **서버가 한다.** 앱은 서버가 알려준 잔액을 보여주기만 한다
- 조각이 모자라면 **만들기 전에** 막는다 — 요금이 나가는 호출을 하지 않는다
- 만들다 실패하면 **조각을 돌려준다**
- 하루 몇 번 같은 별도 제한을 두지 않았다. **잔액이 곧 제한이다**

### 끊겨도 잃지 않는다 (A-1B)

만드는 데 수십 초가 걸리므로 도중에 연결이 끊길 수 있다. 그때 조각만 나가고
그림은 못 받는 일이 없어야 한다.

| 상황 | 앱이 하는 일 |
|---|---|
| 연결이 끊겼다 | "다시 확인"이 뜬다. 눌러도 **새로 만들지 않는다** |
| 이미 만들어져 있었다 | 그 그림을 그대로 받는다 |
| 아직 만드는 중이다 | "아직 만드는 중이에요" |
| 만들다 실패했다 | "조각은 돌려드렸어요" |
| 배경을 못 지웠다 | "배경을 제거하지 못했어요" → **[다시 시도]**. 새로 만들지 않고 같은 그림으로 다시 한다 |
| 앱을 껐다 켰다 | 만들던 스티커를 이어서 확인할 수 있다 |

끊긴 생성은 **다시 확인할 때** 정리된다. 앱을 열지 않으면 그대로 남아 있다 —
저절로 되돌아오지 않으므로 "다시 확인"을 눌러야 결과나 환불을 받는다.

만든 그림은 서버에 **7일** 동안 남는다. 그동안은 다시 받을 수 있다.
영구 보관소가 아니라 **못 받았을 때를 위한 자리**다 — 스티커의 주인은 기기다.

### 프롬프트는 저장되지 않는다

무엇을 적었는지는 그림을 만드는 그 순간에만 쓰인다. 서버도 기기도 남기지 않고, 로그에도
남지 않는다. 다시 편집할 때 필요한 것은 그림이지 그때 뭐라고 적었는지가 아니다.

### AI 스티커는 팔 수 없다 (지금은)

| | |
|---|---|
| 내 거울에 쓰기 | **가능** |
| 사진에 저장 · 공유 (D-1) | **가능** |
| 복제 · 다시 편집 | **가능** |
| 상점에 올리기 | **불가** |

한 번 AI가 들어간 스티커는 그 레이어를 지워도 AI 스티커로 남는다 — 출처는 상태가 아니라
기록이다. 복제해도 물려받는다.

### 아직 아닌 것

이미지를 넣고 바꾸기 · 스타일 고르기 · 여러 장 뽑아 고르기 · 다시 만들기 할인은 없다.
지금은 **한 줄 → 한 장**이다.

## My Stickers (V-5B 확정)

상점은 **거울 / 스티커** 두 칸으로 나뉜다. Bottom Tab은 그대로 홈 / 상점 / 내 거울이다.

상점 → 스티커:

- `스티커 만들기` (빈 캔버스 / 사진으로 시작)
- **내 스티커** — 만든 스티커가 2열로 보인다. 저장하면 **바로** 나타난다(앱 재실행 불필요)
- **스티커 상점** — 서버가 없어서 아직 비어 있다. 가짜 목록을 만들지 않는다

내 스티커 하나를 고르면: 사용하기 / 꾸미기 / 복제 / 상점에 올리기 / 삭제.

- **꾸미기**는 같은 스티커를 고친다. 새 스티커가 생기지 않고 이름도 유지된다.
- **복제**만 새 스티커를 만든다("○○ 복사본").
- 로그인 없이 전부 쓸 수 있다.

## 거울에 놓은 스티커는 그 자리에 고정된다 (중요)

내 스티커를 거울에 놓으면 **그 순간의 모습이 그대로 굳는다.**

- 나중에 원본 스티커를 고쳐도 **이미 꾸민 거울은 바뀌지 않는다**
- 내 스티커 목록에서 지워도 **이미 꾸민 거울은 그대로다**
- 새로 놓을 때는 **최신 모습**이 쓰인다

이미 만든 거울이 나중에 몰래 바뀌거나 스티커가 사라지는 일은 없다.

놓은 뒤의 크기 조절은 기본 스티커와 완전히 같다 — 비율 불변, 최대 크기 제한 없음,
캔버스를 넘어가면 경계에서만 잘린다.

## 스티커 등록 준비

내 스티커 → `상점에 올리기` → **등록 준비**까지다. 실제 등록 · 판매 · 구매는 없다.

- 제목(최대 24자) · 설명(최대 200자) · 가격(0…999 조각)
- 사진이 들어 있으면 "이미지가 다른 사용자에게 보일 수 있어요" 확인이 필요하다
- "직접 만들었거나 사용할 권리가 있는 콘텐츠만" 확인이 필요하다
- **등록 비용은 아직 정하지 않았다.** 거울의 20 조각을 그대로 쓰지 않는다
- 저장해도 조각이 차감되지 않고, 상점에 아무것도 올라가지 않는다

## Currency
- 개념 이름: 거울조각
- UI 이름: 조각
- 아이콘: 5각형 깨진 거울 파편 + 반사선 2개 + 잉크 아웃라인
- 획득: **출석 +1 (구현됨)**. 예정: Rewarded Ad +1(하루 최대 5), IAP 10 / 30 / 70 / 160
- MVP 현금 출금 없음.

**잔액은 server ledger가 정하고, 앱은 그 값을 보여주기만 한다.**
로그인하지 않으면 0으로 보인다.

### 출석 (구현됨 · B-4)

| | |
|---|---|
| 보상 | **+1 조각** |
| 한도 | **Asia/Seoul calendar day 당 1회** |
| authority | **server / Shard Ledger** |
| client 날짜 | 신뢰하지 않는다 |

하루의 기준은 **서버 시계의 Asia/Seoul 날짜**다. 기기 시계를 바꾸거나 앱을 지웠다 깔아도
결과가 같다. 앱은 서버가 돌려준 잔액을 보여줄 뿐, 스스로 +1 하지 않는다.

같은 날 다시 요청해도 조각은 늘지 않고 "오늘 출석 완료"로 답한다 — 오류가 아니다.

### 광고 보상 (server 구현 완료 · production 설정 대기 · B-5)

| | |
|---|---|
| 보상 | **+1 조각** (광고 1회 정상 시청) |
| 한도 | **하루 5회**, Asia/Seoul |
| 하루 기준 | **검증된 Google SSV event timestamp** |
| authority | **검증된 Google SSV callback 하나뿐** |
| 앱의 광고 시청 callback | **경제 authority가 아니다** |

앱이 "광고 다 봤다"고 말하는 것으로는 조각을 주지 않는다. Google이 서버로 직접 보낸
서명된 callback을 검증해야만 지급된다. 그래서 광고가 끝나도 앱은 곧바로 +1을 보여주지 않고
**"보상을 확인하고 있어요"**를 거쳐 서버 값을 다시 읽는다.

광고는 사용자가 **CTA를 직접 누를 때만** 뜬다. 거울 화면에 강제로 나오는 광고는 없고,
전면 광고 · 앱 시작 광고 · 배너도 없다.

**아직 실제로 보상이 나가지 않는다** — 꾸미러 전용 AdMob 광고 단위가 만들어지기 전이라
서버는 지급을 막아두었고(fail closed) 앱도 광고 CTA를 보여주지 않는다.

### 쓰는 곳 (A-1A)

| | |
|---|---|
| AI 스티커 1장 | **6 조각** (서버가 정하고 서버가 차감한다) |

조각을 쓰는 첫 기능이다. 실패하면 서버가 돌려준다.

### 아직 없는 것

IAP · 꾸미러 Pass · 실제 구매.

## 내 콘텐츠 내보내기 (D-1)

내가 만든 것은 앱 밖으로 가져갈 수 있다. **남이 만든 것은 그럴 수 없다.**

| 콘텐츠 | 외부 export |
|---|---|
| 내가 만든 거울 | **가능** — 1080 × 2340 PNG |
| 내가 만든 스티커 | **가능** — 원본 투명도 그대로인 PNG |
| 상점에서 받은 기본 거울 | **불가** |
| 구매한 거울 · 템플릿 | **불가** |
| 다른 creator의 스티커 | **불가** |

구매한 콘텐츠는 **앱 안에서 쓰는 것**까지다. 원본 파일로 꺼내가는 통로를 만들지 않는다 —
판매자가 별도로 다운로드를 허용하는 정책은 D-2에서 다룬다.

내보낸 그림은 **화면 스크린샷이 아니다.** 1080 × 2340 master canvas에 다시 그리므로
기기 크기 · 글씨 크기 설정과 무관하게 항상 같은 결과가 나온다.
편집 화면의 안내선 · 선택 표시 · 핸들은 들어가지 않는다.

저장은 사진 앱 **추가 권한만** 쓴다(사진을 읽지 않는다). 공유는 iOS 기본 공유 시트다.

향후 **AI가 만든 내 콘텐츠(A-1)도 같은 경로**로 내보낸다 — 별도 export를 만들지 않는다.

## Authentication
- 핵심 기능은 로그인 없이 사용.
- Apple 로그인만 지원.
- Store 이용 시점에만 로그인 요구.

### 로그인 없이 되는 것 (확정)

앱은 언제나 Mirror부터 시작한다. **로그인 벽은 어디에도 없다.**

Mirror / Capture / Home / 내 거울 / Editor(그리기 · 스티커 · 사진 스티커 · 텍스트 ·
레이어 · 외부 디자인) / **상점 구경 24장 전부** / 무료 템플릿 받기 / 기기 저장 /
**상점 등록 준비(Draft) 작성과 저장** — 전부 로그아웃 상태로 된다.

### 계정이 필요해지는 것 (아직 미구현)

actual Store Publish · 유료 구매 · 서버 조각 거래 · 판매자 기능.
지금은 이 넷 중 어느 것도 로그인에 연결되어 있지 않다.
연결할 때는 **서버 인증까지 끝난 상태**만 통과시킨다 — Apple 인증만으로는 안 된다.

### 로그인의 의미 (B-2B에서 바뀜)

Apple 로그인 성공 = **꾸미러 서버 계정에 연결된 것**이다.

Apple 로그인 UI를 통과하는 것만으로는 로그인이 아니다. 순서가 이렇다:

1. Apple 로그인 → identityToken
2. 서버가 그 token을 **직접 검증**한다 (앱이 "됐다"고 말하는 것을 믿지 않는다)
3. 서버가 꾸미러 계정을 만들거나 찾는다
4. 서버가 세션을 내준다 → 그때부터 로그인 상태다

2~4 중 하나라도 안 되면 로그인되지 않고, 이해할 수 있는 안내가 뜬다.
**꾸미기는 그대로 계속 쓸 수 있다.**

- 서버가 아는 것은 계정 하나(내부 id)뿐이다. 이름 / 이메일은 서버로 보내지 않고 기기에만 둔다.
- 이름 / 이메일은 Apple이 **첫 로그인에서만** 준다. 다음부터 안 줘도 기존 값을 지우지 않는다.
- 이름을 못 받으면 "Apple 계정"으로 보여준다.
- 계정 삭제 / 서버 사용자 삭제는 만들지 않는다. 없는 기능을 있는 것처럼 보이게 하지 않는다.
- 세션은 30일 뒤 만료된다. 만료되면 서버 로그인만 풀리고 콘텐츠는 그대로다.

서버가 아직 배포되지 않았으므로, **지금 release 빌드에서는 서버 로그인이 되지 않는다.**
"준비 중"이라고 정직하게 알린다 — 되는 척하지 않는다.

### 로그아웃

이 기기의 로그인 상태만 끝난다. 서버 세션을 끊고, 기기에 저장된 계정 정보를 지운다.
Apple 계정 인증 자체는 해제하지 않는다 — 그건 iOS 설정에서 할 일이다.

**네트워크가 안 돼도 로그아웃은 된다.** 서버에 알리지 못하면 남은 세션은 만료로 정리된다.
로그아웃을 네트워크 때문에 막지 않는다.

**로그아웃해도 그대로 남는 것:** 내 거울 / 현재 거울 / 그리기 / 스티커 / 내 스티커 /
사진 스티커 / 외부 디자인 / 상점에서 받은 거울 / 등록 준비 / 스티커 등록 준비 /
보관 슬롯 / 조각.
로그인과 사용자 콘텐츠는 서로 아무 관계가 없다.

Apple 쪽에서 연결이 끊기면(설정에서 해제 등) 로그인만 풀리고, 위 데이터는 하나도 사라지지 않는다.
